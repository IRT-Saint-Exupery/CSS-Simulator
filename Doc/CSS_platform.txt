NB: CFDP alternative implementation is here : https://gitlab.com/librecube/lib/python-cfdp  
NB: CFDP layer is based on external python library , see CF_UPLINK and CF_DOWNLINK commands. The origin filestore is filestore="/home/nos3/Desktop/github-nos3/fsw/build/exe/cpu1/cf".
for now only Class 1 is supported. to be extended.

see Commands:
- CFS CF_UPLINK_FILE --> MsgId 0x18B3
- CFS CF_DOWNLINK_FILE --> MsgId 0x18B6

- for Uplink the flow is : COSMOS --> Cryptolib --> call external CFDP Library (/cf of MCS) --> Send to CryptoLib --> FrontEnd --> ISL --> CI --> BUS --> CF --> Send to external CFDP Server --> save in /cf of SATX
- for Downlink the flow is : COSMOS --> Cryptolib --> FrontEnd --> ISL --> CI --> BUS --> CF ---> call external CFDP library (/cf of SAT X) --> send to CF --> BUS --> TO --> ISL --> FrontEnd ---> Cryptolib --> Send to external CFDP Server --> save in /cf of MCS

NB: Geometric Visibility is computed by ISL when the GPS data are available (NOVATEL activation by TC is required!) the data are then transferred to MCS VM in /tmp folder. See visiX.txt files. 
This is a work around to provide sat visibility to ground station as there is no direct communication between MCS VM and NASA 42 VM. This could be improved in further releases.

NB: Dynamic routing update is managed via frontend that create the uplink command for cryptolib in FE_routegen.cpp.

NB: Cryptolib standalone is compiled at launch on MCS VM. For Cryptolib modifications check at launch on MCS VM.

NB: CSS Attacks packets are labeled to be different from normal packets (this is for detection performance analysis). In particular, 8th octet of SPP is set to 0x02 instead of 0x00 OR 6th bit of 1st octet of TF header is set to 1 instead of 0 (ex. in hex 0x20 becomes 0x24).
